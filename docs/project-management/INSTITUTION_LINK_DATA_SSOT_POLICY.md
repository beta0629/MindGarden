# 기관연계·가예약 — 데이터 정본 정책

제품·배포 공통. 구현 ADR 아님. 스킬 정본: `/core-solution-standardization` 「데이터 정본 vs 임시 소스」. 배포 연동: `/core-solution-deployment`.

| # | 원칙 |
|---|------|
| 1 | **장기 정본은 데이터.** 타기관 내담자(예: 최가을)는 매핑·일정이 처음부터/또는 보정 후 `INSTITUTION_LINK`(기관연계). `SAME_DAY_CARD`(가예약)로 남은 기존 데이터는 **데이터 수정**으로 맞춤. |
| 2 | 소스로 가예약을 기관처럼 취급하는 분기/우회는 **임시 정책**. 데이터 정합 후 제거 후보. 임시 우회로 데이터 오류를 덮지 말 것. |
| 3 | **신규 기능·배포:** 잘못된 타입의 “기존 데이터”를 코드로 계속 수용하지 말고 마이그/운영 보정으로 타입을 바로잡는다. **덮어쓰기 배포 금지**와 함께 동작. |
| 4 | 가예약은 가예약만, 기관연계는 기관연계만 (**배정 배타**). 데이터 타입과 UI 일치. |
| 5 | 회기권 **rem SSOT**와 **승계이력**을 섞지 말 것. |

관련(존재 시): `INSTITUTION_LINK_THEN_VOUCHER.md` — 타기관→바우처 제품 정의(별 SSOT).
