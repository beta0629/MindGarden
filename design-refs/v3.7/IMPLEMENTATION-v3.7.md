# home-v3.7-garden · 웹 구현 노트 (fix10c → 리뉴얼 구현용)

이 묶음은 **fix10c 와 똑같이 보이는 장면 레이어만** 담는다(페이지 바탕·글자·버튼 없음). 새로 그린 것 없음: 같은 .blend·재질·빛·카메라·타이밍, 같은 합성 수식(build_motion_fix10c.py)을 2배 해상도로 다시 낸 것. 히어로는 기존 v1.3 GLB(`v1.3-home/web/hero-butterfly.glb`, 다시 내보내지 않음) 그대로 — 이 묶음에 없음.

- 좌표: 모든 px 는 **CSS px(1x)**. 이미지 파일은 **2x**(파일 px = CSS px × 2). 위치는 페이지 기준(fix9b/fix10c 정지 시안 `home-{1440,390}-fix10c.png` 와 같은 좌표계)과 섹션 기준 둘 다 적음.
- 프레임 = fix10c walk(30 fps, 548 f)의 프레임 번호 `f`. 모든 시퀀스는 매 프레임(1 f 간격) — 크기 목표 안이라 프레임을 건너뛰지 않음.
- 아틀라스: 장면·폭마다 WebP(알파) 시트 몇 장. 칸 = 프레임 + 오른쪽·아래 8px 투명 gutter. `index[i] = [sheet, x, y]`, 칸 크기 `frame_w × frame_h`(2x px). 그리기: `ctx.drawImage(sheet, x, y, frame_w, frame_h, dx, dy, frame_w/2, frame_h/2)`(캔버스는 devicePixelRatio 로 키움). 시트 최대 4096²(1440) / 2048²(390, 모바일 디코드 메모리 ≤16MB/장). 지금 시트와 다음 시트만 디코드해 두면 됨.
- 품질: WebP 색 q82, 알파는 모두 무손실(alpha_quality 100 — 손실 알파는 부드러운 그림자에 띠/등고선이 생김). 대문 몸만 q72(1440)/q74(390)로 크기 목표에 맞춤. 그림자 레이어 색 q70. **대문 그림자 시퀀스·정지 그림자는 1x 파일**(원천 = fix10c 와 같은 50% ShadowCatcher 렌더 ≈ 1x 해상도, 부드러운 그림자) — 같은 CSS 상자에 그리면 됨. 대안 AVIF 는 만들 수 있지만 Safari 16 미만·일부 안드로이드 WebView 디코드가 느려서 WebP 로 통일.

## 0. 스크롤 → 장면 시작(공통 규칙)

fix10c walk 는 각 섹션에서 스크롤이 **멈춘 뒤**(머묾 스크롤 = `viewports-fix9b/scroll-tops.json`) 시간으로 재생된다. 그래서 구현의 기준점(trigger)은 그 머묾 스크롤 위치이고, 장면은 거기서부터 아래 표의 시간(프레임/30 s)으로 재생한다.
섹션 진입 진행률 `p = (scrollY + vh − sectionTop) / (sectionHeight + vh)` (0 = 섹션 위끝이 화면 아래끝에 닿음, 1 = 섹션 아래끝이 화면 위끝을 지남).

|---|---|---|---|---|---|---|
| 1440 (vh 900, 헤더 108) | gate | 공간 cream 1783–2516 | 1747 | 36 | 0.5291 | f174 |
| 1440 (vh 900, 헤더 108) | bench | 후기 cream 3819–4619 | 3783 | 36 | 0.5082 | f320 |

| 390 (vh 844, 헤더 56) | bench | 후기 cream 3363–4109 | 3323 | 40 | 0.5057 | f320 |
| 390 (vh 844, 헤더 56) | booking | 예약 sand 5828–6380 | 5774 | 54 | 0.5659 | f468 |

- 1440 예약 trigger 6342 = 페이지 최대 스크롤(H 7242 − vh 900). 390 은 5774(최대 5776). → 「예약 섹션 p ≥ trigger p 또는 스크롤 끝 − 2px」로 판정.
- 스크롤 스크럽(선택): 손가락으로 되감기를 원하면 trigger 앞 `0.5·vh` 구간에 프레임을 선형으로 매핑해도 같은 프레임을 쓴다(아래 각 장면 프레임 범위). fix10c 기준 동작은 시간 재생.
- **역스크롤 규칙**: trigger 위로 다시 올라가면(scrollY < trigger − 1) 같은 프레임을 **거꾸로** 같은 속도로 재생(대문은 같은 곡선으로 닫힘, 벤치 나비는 같은 경로를 거꾸로 날아 화면 밖/벤치 뒤로). 다시 내려오면 그 자리에서 앞으로. 예약 나비 착지는 한 번만(다시 올라가도 접힌 머무름 유지 — fix10b 규칙).

## 1. 공통: 그림 「자리에 닿기」(대문·벤치, fix9c 그대로)

- **1440**: `hover-angles-1440-00.webp` 각도 29장(85.0°…73.0°, `angles_deg[]`), 캔버스·위치 = 예약 장면과 같음. 미리보기 타임라인 132 f(`angle_index_per_frame`).

- 규칙(fix10b hover 그대로): 포인터(1440)·터치(390)가 나비 영역에 들어온 시각 τ=0 부터 `θ = 85 − 6·smoothstep(τ/0.3 s)·(1 − cos(2π·τ/1.6 s))` (85°↔73°, 조용한 숨), 가장 가까운 각도 프레임을 그림. 떠나면(미리보기: 들어옴 0.8 s, **떠남 3.2 s**, 73°·속도 0) 지금 각도에서 600 ms ease-out 으로 85°. 미리보기 프레임표 그대로 써도 됨.
- 숨쉬기와 함께: hover 동안 숨쉬기(§4)는 멈춤. 들어올 때 숨쉬기 각도가 85°가 아니면 처음 0.3 s 동안 그 각도에서 공식 각도로 섞음(`θ = mix(θ숨, θ공식, smoothstep(τ/0.3))`, 72–73° 는 73° 프레임). hover 가 85°로 돌아오면 숨쉬기를 f509(85°)부터 다시. (fix10c 미리보기는 정지 85°에서 시작한 경우만 보여 줌 — 섞기는 구현 규칙.)
