## 1. 왜 회기권과 다른가

| | 패키지 회기권 (현재 SSOT) | 기관 월계약 (목표 SSOT) |
|--|---------------------------|-------------------------|
| 상품 | N회 패키지 | 기간 계약 (보통 월) |
| 이용 가능 | `ACTIVE` 그리고 `remainingSessions > 0` | 상담일이 **계약 커버 월** 안 (선택 한도 내면) |
| 소진 | rem→0 → `SESSIONS_EXHAUSTED` → 일정·일지 차단 | 월 종료·계약 종료·(있으면) 당월 한도. 회기 소진과 동의어 아님 |
| 결제 | 매핑 건 선입금/당일카드 | 기관 **월 정산** |
| 회차 | 매핑 잔여 산식·`sessionSequence` | 커버 구간 안 **서수**(라벨). 잔여를 만들지 않음 |
| 정산 | 매핑 INCOME/RECEIVABLES | 기관 월 인보이스 |

회기에 큰 숫자를 넣고 매달 리셋하는 방식은 **최가을 유형**(가예약 실패 → CONFIRMED 우회 → rem=0 → 일지 실패)을 반복한다.

## 2. 개념 (이름 가칭 — 공통코드화는 코더)

### 2.1 기관 당사자

상담 테넌트와 **계약을 맺는 외부 기관**(학교·기업·공공 등). `tenantId` 없이 둘 수 없다.

PO가 정할 것: 기관 = 별도 엔티티인가, 테넌트 내 고객 유형인가.

### 2.2 월계약 (SSOT)

- 시작·종료 (월 단위가 기본, 일 단위 경계는 PO)
- 청구 주기 (역월 기본 가정, 합의 전 구현 금지)
- 선택적 당월 한도 (횟수 또는 금액 — **없으면 기간만으로 가능**)
- 상태(유효/정지/종료)는 **공통코드**. Java enum 문자열 하드코딩 금지 게이트(§17 / §1.3)

한 내담자-상담사 매칭은 패키지 회기권 **또는** 월계약 중 하나에 연결한다(공존은 테넌트 안 다른 매칭끼리).

### 2.3 커버 월

상담 `scheduleDate`가 속한 연-월이 계약 기간에 포함되면 일정 가능 후보. 한도가 있으면 그 달 완료·점유 실적과 비교. **`remainingSessions--`가 아님.**

### 2.4 회차 라벨

일지·모달에 필요한 「n회차」는 커버 구간 안 서수. 매핑 rem 산식과 분리. 가예약의 `sessionSequence` null이 일지를 막지 않도록, 월계약 경로의 회차 권위는 **별 규칙**(debugger+PO). 응급 일지 핫픽스와 구현을 섞지 말 것.

### 2.5 정산

기관 × 계약 × 청구월 인보이스. 매핑 `confirm-payment` 1건 = 패키지 1결제와 1:1 매핑 금지. ERP 계정과목은 기존 INCOME 경로를 재사용할지 코더+ERP 표준이 정한다 — 기획은 **단위가 월**임을 고정.

## 3. 권한·정보 노출

| 역할 | 보는 것 | 하지 않는 것 |
|------|---------|--------------|
| ADMIN/STAFF | 기관, 계약 기간, 당월 한도/실적, 정산 상태 | 기관 매칭에 「남은 회기」를 회기권과 같은 필드로 강제 |
| CONSULTANT | 이번 달 이용 가능, 회차 라벨, 일지 가능 | rem=0 이라는 이유로 일지 차단 |
| CLIENT | 계약 월·이용 가능 | 기관 단가·정산 원장 |
| 기관 담당 (후속) | 월 실적·청구 | 상담 일지 본문 |

신규 어드민: **AdminCommonLayout**. 모달: **UnifiedModal**. 공통 모듈 우선.

## 4. 현재 파이프라인과의 관계

`/core-solution-business-flow` 5단계(매칭 → 입금 → 회기 부여 → 스케줄 → 차감/ERP)는 **패키지 회기권** 서술이다. 월계약 테넌트/매칭은:

1. 매칭 (기관 계약에 연결)
2. 계약 유효(월 커버) 확인 — 「회기 부여」 대체
3. 스케줄
4. 완료 시 **실적 기록** (잔여 차감 아님)
5. 월말(또는 합의된 정산일) 기관 청구

패키지 매칭은 기존 5단계를 유지한다.

---

## 5. 캡슐화

- 월계약 판정은 스케줄 서비스·일지 서비스에 흩뿌리지 않고 **한 모듈**(가칭 entitlement/coverage).
- 회기권 판정(`validateRemainingSessions`)과 **호출부를 나눈다.** if-else로 rem을 우회하지 않는다.
- 화면 「잔여」위젯은 회기권 전용. 월계약 카드는 기간/당월 실적 위젯.

구현 시 core-component-manager가 목록 잔여 뱃지 중복을 제안할 수 있다 (코드 직수정 없음).
