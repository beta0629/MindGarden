## 1. 시각 아이디어 · 문장 잇기 줄
종이 질문지의 괘선을 옮겼다. 문항 앞부분과 답이 **같은 괘선 위**에 놓여 한 문장으로 이어진다.
- 내담자: 앞부분(ink 600) 아래 줄에 바로 답(ink2 400)을 쓴다. 왼쪽 번호 여백은 stone 선(`--well-line`)으로 구분. 아이콘·카드 장식 없음.
- 상담사: 앞부분(slate `--sub`) + 답(ink 600)이 한 줄 문장으로 읽힌다. 빈 응답은 점선 빈칸 + 「빈 응답」 배지, 해당 없음은 stone 배지.
- 진행 눈금 50칸: 종이 여백의 번호 눈금. 답함 = ink2, 해당 없음 = stone, 현재 묶음 = 키 큰 ink(빈 칸은 ink 테두리).
- 괘선은 `linear-gradient` 1px 반복(종이 줄 재현). 색 그라데이션 장식 아님.

## 3. 내담자 모바일 (375·414 우선)
### 3.1 셸 = 한 손
```
.m-app  position:fixed; top:var(--vvt); height:100vh → 100dvh → var(--vvh)   (폴백 순서)
 ├ .m-top    상단바 56(키보드 열림 48) + 진행 눈금 · 저장 상태
 ├ .m-scroll 본문만 스크롤 (overscroll-behavior:contain)
 └ .m-bar    하단 엄지 바: 주 버튼 전부 여기. padding-bottom = 12 + safe-area-inset-bottom
```
- 주 버튼(시작하기·확인·동의하고 시작·이전/다음·제출하기·이어서 작성)은 **항상 하단 바**. 화면 위쪽에 주 버튼 없음. 높이 52, 이전 1 : 다음 2 비율(엄지 쪽이 큰 버튼).
- 좌우 여백 `clamp(16px,5.4vw,24px) + safe-area`, 상단 `safe-area-inset-top`. 터치 ≥44(본문 버튼 52). hover는 `(hover:hover) and (pointer:fine)`에서만.
- 입력 글자: 문항 답 17px(아동 20px), 번호·이메일 17px, 모두 ≥16px(iOS 확대 방지). `user-scalable` 막지 않음.

### 3.2 키보드 규칙 (필수)
1. `visualViewport` 높이를 `--vvh`, `offsetTop`을 `--vvt`로 넣는다(`resize`·`scroll` 이벤트). 앱 높이 = `var(--vvh)` → 하단 바가 **키보드 바로 위**에 붙는다. 폴백 `100dvh` → `100vh`.
2. `innerHeight - visualViewport.height > 120`이면 `body.kb`: 상단바 48로 줄이고 진행 메타 한 줄 숨김(눈금은 유지), 하단 바의 safe-area 여백 제거(키보드가 홈 인디케이터를 덮음).
3. `focusin`(textarea·input) 후 250ms에 `scrollIntoView({block:'center'})`. 스크롤 컨테이너는 `.m-scroll`이라 입력은 상단바와 하단 바 **사이**에 온다.
4. 판정(샷 자동 검사): 포커스 입력 bottom ≤ 하단 바 top, 하단 바 bottom ≤ 키보드 top. 375·414 모두 통과(`m11`·`m12`·`m13`).
5. 금지: `position:fixed; bottom:0` 바를 레이아웃 뷰포트 기준으로만 두기(iOS에서 키보드 뒤로 숨음), 키보드 열릴 때 `window.scrollTo` 강제.
- 시안의 키보드는 모의(`?kb=1`, 375=336px·414=346px). 실기기 iPhone Safari·Galaxy Chrome 확인 전 PASS 아님(clinic-os-3).

### 3.4 자동 저장 · 이어서 작성
- 저장 시점: 입력 멈춤 800ms(디바운스), 묶음 이동, 「해당 없음」 토글, `visibilitychange: hidden`. 서버 저장 = 문항 단위 upsert.
- 상단 표시(항상 보임, `role=status`): `저장됨 15:12`(teal 점) · `저장 중…`(amber 점) · `연결 끊김 · 기기에 보관`(amber 점, localStorage 보관 후 재연결 시 재전송).
- 이어서 작성: 링크를 다시 열면 진입 시트가 저장 상태로 바뀌고 주 버튼이 「이어서 작성」. 본인 확인 뒤 **마지막 저장 문항의 다음 묶음**으로 연다. 다른 기기도 같은 링크 + 본인 확인으로 이어짐.
- 본인 확인 전에는 답 내용을 보여 주지 않음(개수·시각만).

### 3.5 동의·보호자 로직
- 만 14세 미만 판정 = **보낼 때 서버 값**(내담자 생년월일 기준 `requires_guardian`). 내담자 화면에서 나이를 묻지 않는다.
- `requires_guardian`이면 본인 확인 → 보호자 동의 → 안내(아이용) 순서. 받는 곳은 보호자 번호.
- 민감정보 동의·보호자 동의는 **질문지 건마다** 기록: 동의 시각, 동의 문구 버전, 보호자 이름·관계·인증 번호 끝 4자리.
- 동의하지 않으면 시작 불가. 「동의하지 않아도 상담은 받을 수 있습니다」를 함께 안내.

## 6. 접근성
- 문항 = `<label for>` 앞부분 + `<textarea aria-label="n번 답">`. 해당 없음 = `aria-pressed`. 동의 = `role=checkbox aria-checked`. 세그먼트 = `role=radiogroup/tab`.
- 저장 상태 `role=status`(읽어 주되 매 입력마다 반복하지 않도록 상태가 바뀔 때만 갱신). 오류 `role=alert` + 입력 `aria-invalid`/`aria-describedby`.
- 포커스: 공통 `0 0 0 3px #fff, 0 0 0 5px ink`. 문항 답칸은 현재 문항 줄 배경 slate50 + 괘선 ink2.
- 대비: 본문 ink·ink2 on cream/white ≥ 4.5:1, 보조 글 mute `#64748B` ≥ 4.5:1(흰 바탕).
- 색만으로 상태를 말하지 않음: 상태 배지 글자, 빈 응답 점선+글자, 눈금은 보조(숫자 함께 표기).
- `prefers-reduced-motion`이면 시트 상승 모션 끔. 말줄임 없음(이름·문항·답 전부 줄바꿈).
