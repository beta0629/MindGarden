## 6. 환불 행 표기 규칙 (별도 절 · 「-1」 오류 대응)

필드명은 **구현 시 확인** (Cursor가 코드에서 확정). 여기서는 규칙만 확정.

### 6-1. 상품 칸 = 항상 원 상품명
| 순서 | 값 |
|---|---|
| 1 | 원주문/원결제의 상품명 (구현 시 확인) |
| 2 | 행 자체의 상품명 (센터 매핑: 코드상 `productTitle` → `packageName` 순) |
| 3 | **폴백 「상품 정보 없음」** 14/500 `#64748B` (기울임 없음 · 링크 없음) |
- 숫자만 있는 문자열(`/^[-+]?\d+([.,]\d+)?$/`, 예 「-1」 「1」)·빈 문자열은 **상품명이 아닌 것으로 보고** 다음 순서로 넘어감.
- 온라인 주문 폴백 「쇼핑 주문」도 「상품 정보 없음」으로 통일.

### 6-2. 수량·회기 = 음수 노출 금지
| 원본 | 표시 (상품 2줄 12.5 mute) |
|---|---|
| +10 | 10회기 |
| −10 (또는 환불 행의 10) | **10회기 환불** |
| −1 | 1회기 환불 |
| 0 · null | 줄 생략 (검사 상품 등) |
화면 어디에도 「-」 부호가 붙은 수량·회기·금액을 쓰지 않음.

### 6-3. 금액 = 절댓값 + 환불 문맥
마이너스 기호·빨간 음수·원금 취소선 **모두 금지**. 금액 칸 숫자는 항상 ink, 환불은 배지와 보조줄로 알림.

| 경우 | 상태 배지 | 금액 칸 (1줄 · ink) | 보조줄 (12.5 mute · 오른쪽) | 상품 2줄 |
|---|---|---|---|---|
| **A. 원결제 행이 상태만 바뀜 · 전액** | 환불 | 결제액 「90,000원」 | 「전액 환불」 | 「{n}회기」 |
| **B. 원결제 행이 상태만 바뀜 · 일부** | 부분환불 | 결제액 「100,000원」 | 「환불 30,000원」 | 「{n}회기」 (환불 회기를 알면 「{n}회기 · {m}회기 환불」) |
| **C. 환불이 별도 행 · 전액** | 환불 | 환불액 절댓값 「90,000원」 | 원결제를 알면 「{YYYY.MM.DD} 결제분」, 모르면 생략 | 「{n}회기 환불」 |
| **D. 환불이 별도 행 · 일부** | 부분환불 | 환불액 절댓값 「30,000원」 | 「결제 100,000원 중」 (원결제액을 알 때) | 「{m}회기 환불」 |
| C·D의 원결제 행 | 데이터 상태 그대로 (보통 완료) · 부분/전액 환불이 확인되면 A·B처럼 배지 교체 | 결제액 | A·B 규칙 | 「{n}회기」 |
| 취소 · 실패 | 취소 / 실패 | 금액 `#64748B` (돈이 안 나감) · 취소선 없음 | 없음 | 「{n}회기」 |

- **부분환불 판정** (전용 원본 값이 없을 때): 환불액 > 0 이고 환불액 < 결제액 → 부분환불 · 환불액 = 결제액 → 환불.
- 별도 환불 행 날짜 = **환불일** · 원결제 행 날짜 = 결제일.
- **합계 중복 방지:** refundSum은 별도 환불 행이 있으면 그 행만 더하고, 같은 원결제에 대해 A·B의 환불액을 다시 더하지 않음 (원결제 ID로 묶기 · 구현 시 확인). paidSum은 원결제 행의 결제액만 (별도 환불 행 금액은 결제액에 넣지 않음).
- 필터 「환불」 = A·B·C·D 모두 · 「완료」에는 C·D 행이 들어가지 않음.

### 6-4. FE 공통 포맷터 (화면에서 직접 포맷 금지 · 공통 util 한 곳)
| 함수 (이름은 구현 시 확인) | 입력 | 출력 규칙 |
|---|---|---|
| `formatWon(value)` | number · 문자열 숫자 · null | null/NaN → 「—」 · **`Math.abs`** · 반올림 · `toLocaleString('ko-KR')` + 「원」 · 반환 `{ text, isNegative }` · 「-」「₩」 출력 금지 |
| `formatSessions(n, { refund })` | 정수 | 0/null → `null`(줄 생략) · `Math.abs(n)` + 「회기」 · `n < 0` 또는 `refund` → 뒤에 「 환불」 |
| `resolveRefundContext(row)` | 행 | 음수 금액·음수 회기·환불 상태 중 하나라도 있으면 `{ refund: true, partial }` → 배지·보조줄·「환불」 문맥을 **호출부가 반드시** 붙임 (음수를 문맥 없이 절댓값만 찍는 것 금지) |
| `resolveProductName(row, original)` | 행 + 원주문 | §6-1 순서 · 숫자만/빈 값 제외 · 폴백 「상품 정보 없음」 + `isFallback` |
| `formatDate(iso)` | ISO | 로컬 `YYYY.MM.DD` · null → 「—」 |
기존 `Intl.NumberFormat(currency:'KRW')`(₩) 호출은 이 화면에서 제거.

## 8. 페이지네이션

**공통 리스트 모듈(page/size)을 그대로 쓴다 — size·페이지 버튼·문구를 화면별로 하드코딩하지 않는다.**
- 두 출처를 합친 뒤 모듈에 넘겨 **클라이언트 페이징** (정렬 = 표시 날짜 내림차순) · 필터 바뀌면 page 1.
- 지금 온라인 주문 조회가 `page=0&size=50` 고정 → 50건 넘는 내담자는 옛 주문이 빠짐. 백엔드 변경 없이 모듈의 page/size로 끝까지 읽기 (구현 시 확인).

## 11. 확인 필요

1. **부분환불 원본 값·필드** (전용 상태값 유무, 환불액 필드) — 없으면 §6-3 금액 비교.
2. **별도 환불 행의 원결제 연결 키** (원주문/원매핑 ID) — 상품명 복원·합계 중복 방지에 필요.
3. 리더 스샷의 「9/30 신용카드 · 수동/센터 · 환불완료 · '-1'」 행의 원본 필드 (확인 시점 .dev 데이터에 없었음).
4. 온라인 주문 응답에 상품명 필드 없음 (`title`/`orderName` 폴백 코드만 있음) → 상품명을 FE만으로 얻을 수 있는지 (주문 상세 API 재사용 등). 안 되면 「상품 정보 없음」.
5. 온라인 결제 「일시불」 고정 여부 (할부 가능하면 문구 수정).
6. 기간 필터를 클라이언트에서 거를 때 기준 날짜 = 결제일(없으면 생성일)로 충분한지.
7. `₩` → 「원」 전환이 내담자 웹 전체 방향인지 (몰 스펙 §14-1과 같은 질문).
8. 내담자 화면이 `/api/v1/admin/mappings/client`(admin 경로)를 부르는 것 — 권한·경로 정책 확인 (이번 범위는 FE만이라 변경 안 함).
9. 태블릿(768–1023) stage pad 값이 셸 공통에 있는지 (없으면 이 문서 값).
10. 공통 리스트 모듈의 기본 size와 클라이언트 페이징 지원 여부.
